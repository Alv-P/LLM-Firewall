Prompt Injection Firewall For AI

A reverse-proxy security layer that classifies prompts and documents for adversarial injection risk before they ever reach a downstream LLM.

Honeypot Mode When ON, flagged attempts get a plausible fake reply instead of an explicit denial — the attacker can't tell it was blocked. Applies to both public features below. All original protections still apply underneath.

Chat with a document

How the honeypot works

Every message and document is still classified exactly the same way — keyword matching, then a consolidated LLM-based check across phrasing, structure, hidden content, and embedded code. Nothing about detection changes between the chat and document-upload surfaces. What changes is only the response surface: instead of an explicit "blocked" message that confirms to an attacker their attempt was noticed, a flagged request receives a fabricated, harmless-sounding reply — generated under strict rules that forbid revealing real system information or providing any genuinely usable harmful content. The real classification result is logged server-side for admins, never exposed to the public response.

Admin Access

Transparent, non-deceptive classification results are restricted to authenticated admin/company use for testing purposes — both chat and document endpoints below share this key.

Private Chat Testing

The admin equivalent of the public chat — no document, no honeypot deception. Returns the real SAFE / FLAGGED classification and, when SAFE, the underlying model response. Built for genuine red-team testing of the direct-injection detection path.

Document Classification Testing

Upload a document and a question. Unlike the public surface, this endpoint returns the real SAFE / FLAGGED result with no deception — built for genuine red-team testing of the indirect-injection detection path.
